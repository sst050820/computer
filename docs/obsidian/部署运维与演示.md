# 部署运维与演示

---

## 一、快速启动

### 环境要求

| 组件 | 版本 | 必需? |
|------|------|-------|
| Docker | 20.10+ | ✅ MySQL 容器 |
| Go | 1.25+ | ✅ 编译后端 |
| Java | 17+ | ❌ ABE 服务（不可用则降级） |
| Fabric | 2.3 | ❌ 区块链（不可用则跳过） |

### 一键启动

```bash
cd ~/program
make start
# 等价于: bash scripts/start_all.sh
```

脚本做的事：

```
[1/4] 启动 MySQL (Docker mysql-fruit, 端口3306)
[2/4] 启动 Fabric (可选, 失败跳过)
[3/4] 启动 Java ABE 密码学服务 (推荐, 不可用则降级明文)
[4/4] 编译 Go 后端 → 杀掉旧进程 → 启动 (:8080)
```

### 分步启动

```bash
# Step 1: MySQL
docker start mysql-fruit 2>/dev/null || docker run -d --name mysql-fruit \
  -e MYSQL_ROOT_PASSWORD=123456 -e MYSQL_DATABASE=fruit_platform \
  -p 3306:3306 mysql:8.0 --character-set-server=utf8mb4
sleep 5

# Step 2: 后端
cd backend && go build -o server . && nohup ./server > ../logs/backend.log 2>&1 &

# Step 3: 浏览器访问 http://localhost:8080
```

### 停止

```bash
make stop
# fuser -k 8080/tcp         # 停止后端
# pkill -f CryptoServer     # 停止 ABE 服务
# docker stop mysql-fruit   # 停止 MySQL (保留数据)
```

## 二、服务端口

| 服务 | 端口 | 说明 |
|------|------|------|
| Go 后端 | `8080` | HTTP API + 前端静态文件 |
| Java ABE | `8081` | 密码学服务（可选） |
| MySQL | `3306` | 数据库 |

## 三、环境变量

复制 `.env.example` 为 `.env` 按需修改：

```ini
# MySQL
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=123456
DB_NAME=fruit_platform

# 后端端口
BACKEND_PORT=8080

# ABE 加密服务（可选）
ABE_SERVICE_URL=http://localhost:8081/api/encrypt
ABE_DECRYPT_URL=http://localhost:8081/api/decrypt
ABE_REVOKE_URL=http://localhost:8081/api/revoke
ABE_REKEY_URL=http://localhost:8081/api/rekey
ABE_REENCRYPT_URL=http://localhost:8081/api/reencrypt

# Fabric 区块链（可选）
FABRIC_BASE_PATH=/home/sitong/HyperledgerFabric/fabric-samples/test-network

# 前端路径（可选）
FRONTEND_ROOT=/home/sitong/program/frontend
```

## 四、数据库操作

### 连接

```bash
docker exec -it mysql-fruit mysql -uroot -p123456 fruit_platform
```

### 常用查询

```sql
SELECT id, username, name, role FROM users;
SELECT id, holder_name, qual_type, qual_value, status FROM qualifications;
SELECT id, name, category, origin, price FROM products;
SELECT id, title, policy, status FROM custom_orders;
```

### 重置

```bash
docker rm -f mysql-fruit
# 重新 docker run... 然后重启后端即可自动初始化
```

## 五、故障排查

| 现象 | 检查 |
|------|------|
| MySQL 连接失败 | `docker ps \| grep mysql-fruit` |
| 端口占用 | `fuser 8080/tcp` |
| ABE 不可用 | **正常现象**，系统自动降级，查看日志确认 `[WARN]` |
| Fabric 不可用 | **正常现象**，仅区块链追溯功能不可用 |
| 日志位置 | `logs/backend.log`，`tail -f` 实时查看 |

## 七、核心演示场景

### 场景 A：ABE 加密发布 + 解密 ⭐（最重要）

```
1. 登录 shike（消费者）
2. 「私人定制」→ 填写需求：
   标题: "福建有机茶饼定制"
   描述: "需要200斤有机铁观音茶饼，送礼包装"
   条件: Location=福建, Capability=制茶
3. 发布 → 需求被 ABE 加密

4. 换 fujianmingpin 登录（福建名品茶厂，有 Location=福建 + Capability=制茶）
5. 「需求市场」→ 看到需求 → 「ABE 解密验证」
6. ✅ 解密成功！显示需求原文 → 可接单报价

7. 换 shandongfengshou 登录（山东丰收食品厂，只有 Location=山东）
8. 「需求市场」→ 看到需求 → 「ABE 解密验证」
9. ❌ 解密失败！显示"产地不满足（你是山东，需求要福建）"
```

### 场景 B：审核方撤销属性

```
1. 登录 fujiangongshang（福建省工商认证中心）
2. 「资质管理」→ 找到福建名品茶厂的 Location=福建 资质
3. 点击「收回」→ 确认（弹窗提示 ABE 撤销）
4. 资质状态 → revoked，ABE 属性被撤销

5. 换 fujianmingpin 登录 → 再次尝试解密 → 失败（Location 属性已失效）
```

### 场景 C：管理员密钥轮换

```
1. 登录 admin / admin123
2. 「规则管理」→ 查看当前认证规则
3. 点击「更新认证规则」→ 确认
4. 所有 active 资质 → expired
5. 所有商家需重新申请资质
```

### 场景 D：监管方追溯查询

```
1. 登录 shiyaojian
2. 「产品档案查询」→ 选择"武夷山大红袍"(p1)
3. 查看全链路追溯时间线：
   🟢 种植 → 加工 → 到店（公开节点）
   🔴 质检 → 运输（加密节点，仅监管方可查看）
4. 「应急处理」→ 可紧急解密加密节点
```
